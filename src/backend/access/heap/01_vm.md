# Why & How: Visibility Map (VM)

## 1. 定义

**Visibility Map（VM）**：堆关系的独立 fork（`<relfilenode>_vm`，`VISIBILITYMAP_FORKNUM`），按 **堆页** 记两个 **hint** 位：

| bit | 常量                          | 含义                                                     |
| --- | --------------------------- | ------------------------------------------------------ |
| 低   | `VISIBILITYMAP_ALL_VISIBLE` | 该页所有 tuple 对**所有事务**可见 → 无 dead tuple，VACUUM 可跳过（普通清理） |
| 高   | `VISIBILITYMAP_ALL_FROZEN`  | 该页所有 tuple 已 freeze → 防 wraparound 的整表 VACUUM 也可跳过     |

- 只服务 **heap**（及 toast / matview 等堆关系）；**索引没有 VM**。
- 保守：bit **置 1 ⇒ 条件成立**；bit **为 0 ⇒ 不知道**（可能已经全可见，只是还没扫到）。
- `all-frozen` 只能在已经 `all-visible` 时置位。

源码：`src/backend/access/heap/visibilitymap.c`、`visibilitymap.h`。

对比 [FSM](../../storage/freespace/01_fsm.md)：同是关系 fork、按页摘要；FSM 回答「有没有空位」，VM 回答「要不要再看这一页」。

---

## 2. 为何需要

堆页可见性的权威在 tuple 头（`xmin`/`xmax` + hint bit），见 [MVCC Visibility](../transam/08_mvcc_visibility.md)。每页都打开堆做 `HeapTupleSatisfies*` 在两类路径上太贵：

1. **Index Only Scan**：索引已有列值，还缺「这一行对当前快照是否可见」。若堆页 all-visible，**所有**现存 tuple 对任何快照都可见，可跳过 heap fetch。
2. **VACUUM**：all-visible 页没有可回收 dead tuple，普通 vacuum 可跳过；all-frozen 页连 anti-wraparound 扫描也可跳过。

没有 VM 就只能每页探堆。VM 把「这一页还要不要碰」收成 fork 上的 2 bit。

置位几乎只由 **VACUUM** 完成；任何改堆页内容、破坏「全员可见 / 已冻结」的操作（insert / update / delete / lock tuple 等）必须 **清位**。

---

## 3. 页内结构：无树的 bitmap

每个 VM 页：标准页头 + 其后整段 bitmap，**没有** FSM 那种 max 树。

- `MAPSIZE = BLCKSZ - MAXALIGN(SizeOfPageHeaderData)`
- 每堆页 2 bit → 每字节覆盖 4 个堆页
- 默认 8k 页：约 **32672** 个堆页 / 1 个 VM 页
- 堆块号 `x` → `(mapBlock, mapByte, mapOffset)` 线性换算

不需要树：查询是「这一页的 bit 是什么」，不是「找一个满足条件的页」。

堆页头另有 `PD_ALL_VISIBLE`，语义与 VM 的 all-visible 相同，但落在数据页上。正常应一致；crash 后可能出现「堆页已置、VM 未置」（保守，安全）——反过来（VM 置而堆页未置）会让后续 DML **漏清 VM**，Index Only Scan 可能读到不该可见的行。

---

## 4. WAL：置位要记，清位搭便车

同一事实存了两份：

- **堆页头** `PD_ALL_VISIBLE`：改这一页的进程已经 pin 了堆页，看这个 bit 决定「要不要去清 VM」。
- **VM fork** 上对应的 all-visible：Index Only Scan / VACUUM 不读堆页时用。

DML **先看堆页标志再决定清不清 VM**。因此只允许一种暂时不一致：堆页已经 `PD_ALL_VISIBLE`、VM 还是 0（保守，IOS 多访一次堆）。**禁止**反过来：VM=1 而堆页标志=0 —— 下次 INSERT/UPDATE 不会去 `visibilitymap_clear`，IOS 仍当全可见、跳过堆，可能读到错行。

这就是不变量（[transam README · 提示](../transam/00_readme.md)）：

**VM all-visible = 1 ⇒ 堆页必须已有** `PD_ALL_VISIBLE`**。**

| VM-bit(_vm) | PD_ALL_VISIBLE(page) | 是否允许  |
| ----------- | -------------------- | ----- |
| 0           | 1                    | 是     |
| 0           | 0                    | 是     |
| 1           | 1                    | 是     |
| 1           | 0                    | **否** |

崩溃时两份各自落盘，WAL 因此不对称：

- **置位必须记。** VACUUM 写 `log_heap_visible`。最坏是 VM 页先落地、堆页标志仍 0——不变量破了，redo 靠这条把标志补上。`visibilitymap_set` 因此把 **VM 页 LSN** 推到这条记录，bufmgr 不会在 WAL flush 之前写出 VM 页。
- **清位搭便车。** 不单独给 VM 记 WAL，清位塞进这次 INSERT/UPDATE/DELETE 的 redo。清成 0 永远安全；最坏是没清掉，redo 再清一次。所以不必推 VM 的 LSN。

`PD_ALL_VISIBLE` 介于 hint 和持久修改之间（[transam README · 编写提示](../transam/00_readme.md#编写提示)）：

- **清**：永远当持久修改（普通 WAL）。否则崩溃后堆页标志丢了、VM 还在，正好落到禁止的那一侧。
- **置**：VM 页照常更新 LSN；堆页分两种：
  - checksum / `wal_log_hints` **开着**：堆页也当持久修改（带 FPI），防半页撕裂。
  - **都关**：只改这一个标志，撕裂不致命，**不写堆页 FPI、也不更新堆页 LSN**。否则后来的 UPDATE 会凭偏高的页 LSN 跳过 FPI，checkpoint 后崩溃可能丢掉真正的元组数据。

## 5. 对外 API 与调用路径

| 函数                                                   | 作用                                             |
| ---------------------------------------------------- | ---------------------------------------------- |
| `visibilitymap_pin` / `pin_ok`                       | 钉住对应 VM 页（可能 I/O、扩展 `_vm`）；**不要**在持有堆页锁时做 I/O  |
| `visibilitymap_set(rel, heapBlk, heapBuf, …, flags)` | 调用方已写好 `PD_ALL_VISIBLE`；在已 pin 的 VM 页上置位并记 WAL |
| `visibilitymap_clear(rel, heapBlk, vmbuf, flags)`    | 清指定 bit；禁止只清 visible 而留下 frozen                |
| `visibilitymap_get_status`                           | 读 2 bit；通常 **不加锁**，调用方处理竞态                     |
| `visibilitymap_count`                                | 近似统计 all-visible / all-frozen 页数               |
| `visibilitymap_prepare_truncate`                     | 堆 truncate 时收缩 `_vm`                           |

**VACUUM 置位**（持有堆页锁，防止刚看完「全可见」就被别人改页）：

```text
VACUUM 扫堆页、必要时 freeze
  -> 确认全可见 / 已冻结
  -> 先 pin VM（无堆锁）
  -> 锁堆页、复核
  -> 置 PD_ALL_VISIBLE
  -> visibilitymap_set（WAL）
```

**DML 清位**（与堆页修改同一临界区，crash-safe）：

```text
看堆页（尚未加锁）：若 PD_ALL_VISIBLE → 先 pin VM
锁堆页
  若其间 VACUUM 刚置了 PD_ALL_VISIBLE 而 VM 未 pin
    -> 放锁、pin、再锁
改 tuple + XLogInsert
  同一临界区 visibilitymap_clear
```

**Index Only Scan**（`nodeIndexonlyscan.c`）：

```text
索引取 TID
  -> visibilitymap_get_status
       all-visible -> 不再访堆（仍持有索引叶 pin，避免 TID 回收竞态）
       否则 heap fetch + HeapTupleSatisfiesVisibility
```

观测：contrib `pg_visibility`；可复现步骤见 [trace: VM](../../../traces/05_vm.md)。

- Fork：`VISIBILITYMAP_FORKNUM`

---

## 7. 小结

1. VM = 每堆页 2 bit（all-visible / all-frozen）的保守 bitmap，加速 VACUUM 跳页与 Index Only Scan。
2. 置 1 只由 VACUUM（持堆锁 + WAL）；DML 必须清位；bit 为 0 不能当「不可见」。
3. 正确性靠 **VM bit 与** `PD_ALL_VISIBLE` **同向**：VM 为 1 时堆页标志必须在；否则 IOS 与后续清位都会错。这与 FSM「错了只是多 extend」不同。
