# PostgreSQL `wal_level` 核心参考

```c
/* WAL levels */
typedef enum WalLevel
{
	WAL_LEVEL_MINIMAL = 0,
	WAL_LEVEL_REPLICA,
	WAL_LEVEL_LOGICAL
} WalLevel;
```

## 概述

内核枚举 `WalLevel`，映射至配置参数 `wal_level`。控制 WAL 日志记录粒度，直接决定数据库的容灾、复制与数据同步能力。

## 级别定义

| 级别          | 日志粒度              | 核心能力                  | 典型场景                           |
| :------------ | :-------------------- | :------------------------ | :--------------------------------- |
| `MINIMAL` (0) | 事务/页级元数据       | 仅单机崩溃恢复            | 临时库、压测环境、极致写入优化     |
| `REPLICA` (1) | 完整页修改 + FPW      | 物理流复制、WAL归档、PITR | **生产默认值**，主从架构、定期备份 |
| `LOGICAL` (2) | 行级变更 + 旧值上下文 | 逻辑复制、CDC、异构同步   | 实时数据管道、跨库同步、Debezium   |

## 核心约束

- **生效机制**：修改后必须**重启实例**。
- **能力继承**：`LOGICAL ⊃ REPLICA ⊃ MINIMAL`，高级别天然兼容低级别功能。
- **降级红线**：从 `LOGICAL` 降级前必须**删除所有逻辑复制槽**，否则 WAL 无法回收，磁盘将迅速爆满。
- **开销基线**：`REPLICA` 为性能/可靠性最优平衡点；`LOGICAL` 增加 `20%~50%` WAL 体积及额外序列化 CPU 开销。

## 选型决策

```
是否需要物理主从或时间点恢复(PITR)？ ──是──> REPLICA
是否需要逻辑复制/CDC/实时流处理？   ──是──> LOGICAL
是否可接受数据丢失且仅需单机恢复？  ──是──> MINIMAL
```

> 💡 **工程建议**：无特殊 CDC 需求时，锁定 `REPLICA`。开启 `LOGICAL` 需同步规划复制槽监控与 WAL 磁盘水位告警。
